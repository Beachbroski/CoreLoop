### [blocker/design] Draft A §2 "Theme stamping": the public/marketing route group and the auth pages stamp data-theme="dark" on <html> from their layout; the dashboard layout runs a tiny inline script to apply the stored value before first paint.

**Evidence.** `find app -name 'layout.tsx'` returns exactly four files: app/layout.tsx, app/(dashboard)/layout.tsx, app/(dashboard)/brand/layout.tsx, app/(dashboard)/creator/layout.tsx. **Fix.** Drop A's stamping rule and adopt Draft B §2.3 verbatim: stamp data-theme on a `.cd-app` wrapper div rendered by PublicPageShell / each auth page / the brand layout, with the brand layout reading a cookie via `await cookies()` (it is already dynamic via getCurrentAppUser). ### [blocker/engineering] Draft B §3.1 "File-collision audit: the only files touched by more than one package are app/globals.css, package.json and eslint.config.mjs... No two packages in the same wave share a file."

**Evidence.** Draft B §2.5 states "Component CSS files are pulled into app/styles/index.css via @import so the production order is fixed, and each component imports nothing at all". app/styles/index.css is owned solely by WP-04 (wave 1). WP-05 (wave 1) and WP-07, WP-08, WP-09, WP-10, WP-11, WP-13 (all wave 2) each create colocated component .css files that must therefore be registered in that one file — six concurrent packages editing a file owned by a seventh. WP-04's own acceptance criterion makes it worse: "index.css @imports in order: tailwindcss, ../globals.css, tokens.css, base.css, then each component sheet" — a CSS @import of a file that does not yet exist fails the build (postcss-import resolves at build time, per node_modules/next/dist/docs/01-app/01-getting-started/11-css.md:458).

**Fix.** Either (a) have each component .tsx import its own colocated .css directly — Next supports this (11-css.md:294) and the Suspense caveat only affects cross-route unloading, not ordering within a page — or (b) keep the single entry file but make the @import manifest owned and edited by the orchestrator at each wave gate, not by package agents. Whichever is chosen, add app/styles/index.css to the collision audit and re-run that audit over the full owned-file lists.
