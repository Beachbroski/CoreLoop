# CreatorDocks iOS app

The creator-facing app: discover paid campaigns from local brands, apply,
submit content, track submission status, and get paid. Expo (SDK 57) +
`expo-router`, React Native 0.86, TypeScript strict, React 19.2.3.

Creators are moving here from the web dashboard — see the repo root
`README.md` and `docs/platform-split/03-ios-app.md` for the product context,
and `docs/platform-split/00-MASTER-PLAN.md` for the overall split. This app
talks to the same Next.js backend as the web app, over a separate
Bearer-token API namespace: `/api/v1/*` (`../lib/mobile-api-guard.ts` and
`../app/api/v1/`), not the web's cookie session.

## Prerequisites

- **Xcode** (for the iOS Simulator and native builds).
- **A dev client build — Expo Go will NOT work.** This app uses native
  modules (`react-native-reanimated`, `expo-notifications`, `expo-glass-effect`,
  Clerk's native OAuth flows, etc.) that aren't present in the generic Expo Go
  sandbox. You need a custom development client, built once via `expo run:ios`
  / `xcodebuild`, then reused with `expo start --dev-client`.
- The backend running locally (or a reachable API URL) — see below.

## Running the app

1. Install dependencies from the repo root (this is an npm workspace, not a
   standalone package):
   ```bash
   npm install
   ```
2. Start the backend first, from the repo root:
   ```bash
   npm run dev
   ```
3. From `mobile/`, start Metro with the dev client:
   ```bash
   npx expo start --dev-client
   ```
4. Build and install the native dev client on the simulator (only needed the
   first time, or after adding/upgrading a native module):
   ```bash
   xattr -cr mobile/ios
   npx expo prebuild --clean
   npx expo run:ios
   ```

`mobile/ios` (and `mobile/android`) are **generated by `expo prebuild`, not
checked in** — `mobile/.gitignore` excludes them. Don't hand-edit files under
`mobile/ios`; re-run `prebuild` instead.

### The iCloud extended-attribute codesign trap

This repo lives under an iCloud-synced `Desktop` folder. iCloud attaches
extended attributes (`com.apple.fileprovider.ubiquity#…`, etc.) to synced
files, and Xcode's codesigning step fails on files carrying them — this shows
up as an opaque codesign/build failure inside `mobile/ios` that has nothing to
do with your actual code change.

**Run this before every clean build** (i.e. whenever you've just run
`expo prebuild`, pulled changes that touched native config, or are debugging a
codesign failure that doesn't reproduce on non-iCloud machines):

```bash
xattr -cr mobile/ios
```

If a build fails with a codesigning error and this hasn't been run recently,
run it and rebuild before looking anywhere else.

## Environment variables

Set in `mobile/.env` (gitignored) for local development:

| Variable | Purpose |
| --- | --- |
| `EXPO_PUBLIC_API_URL` | Base URL of the backend's `/api/v1` API (e.g. `http://localhost:3000` for the local backend). Read in `src/lib/api-client.ts` and `src/lib/uploadthing.ts`; the app throws if it's unset. |
| `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY` | Clerk's **publishable** key (`pk_test_…` / `pk_live_…`), read implicitly by `@clerk/clerk-expo`'s `<ClerkProvider>` in `src/app/_layout.tsx`. |

Both are `EXPO_PUBLIC_*`, meaning they're inlined into the JS bundle at build
time and are not secret — never put a Clerk **secret** key or anything else
sensitive behind an `EXPO_PUBLIC_*` name. There is currently no tracked
production configuration for these (no EAS project, no `app.config.ts`
per-profile env) — see `mobile/RELEASE-CHECKLIST.md` and
`docs/production-readiness-2026-09-06.md` for what's still needed before a
real build can point at production.

## Test, lint, typecheck

From `mobile/`:

```bash
npx tsc --noEmit    # strict TypeScript
npx expo lint       # ESLint (eslint-config-expo)
npx jest            # jest-expo unit/render tests
```

## Before shipping a build

Read `mobile/RELEASE-CHECKLIST.md` first — it tracks release blockers that
can't live in `app.json` (Expo parses that file as strict JSON, so it can't
carry comments, and anything under `expo.extra` ships to every device in the
runtime manifest). It currently covers the Apple App ID / bundle identifier,
the EAS project (push notifications are inert without it), and the App Store
URL that `VersionGate` needs.

For the full pre-launch picture (TestFlight, App Store review, parity with
web, the creator-web sunset sequencing), see
`docs/platform-split/08-release-qa-sunset.md` and
`docs/production-readiness-2026-09-06.md`.
